For a mechanical stress calculation, **10×** means multiplying aggregate Luna input, the cached-input subset, and output each by ten, with Terra, Sol and Astra counts unchanged. It is a token-volume counterfactual, not tenfold useful findings, agents, simultaneous jobs, reasoning effort, or a recommendation. The directive instead proposes an aspirational tenfold increase in *useful eligible investigation* relative to a defined prior unit; this exercise cannot establish that increase. The narrow pump task may only support roughly 1.5–3× the old Luna token budget before work becomes repetitive; the bounded foundation converter campaign might plausibly need 1–2× under the same scope. These judgment ranges are not cost confidence intervals or evidence of useful findings. The selected 2.5× pump and 1.5× foundation Luna-input points below are illustrative, with output chosen separately; a full 10× is conditional on demonstrably distinct useful cases and is not forced into either narrowly scoped example.

## Accounting

Counts are aggregate **thousands of tokens** for all turns, and cached input is included in input, never added to it. Each base budget attempts to cover inherited instructions, tool-result context, repeated context/cache reads, coordination, Terra screening where applicable, hidden reasoning billed as output, expert source review, integration, independent review, and a modest repair reserve. Full common prompt overhead is unmeasured, so these are not verified all-inclusive budgets; the prompt sensitivity below shows the effect of omitted context. Counts are guesses; context lengths and real cache hits could differ. The same acceptance categories are intended in all three columns, without a frozen case inventory or controlled comparison: A is the frozen scenario, B is the mechanical stress case, C is a conservative overhead case grounded in current policy, not a statistically expected allocation. C includes extra screening and preserves consequential expert work; it is not a claim of saved work. C versus A combines updated scope assumptions with the policy forecast and therefore cannot isolate any causal effect of the directive. Reducing the foundation worker forecast corrects the earlier planning granularity based on the refreshed scope, not a measured efficiency gain. B isolates only mechanical Luna token scaling; the same acceptance categories remain in each scenario. The original A aggregate budgets are kept exactly as published.

The [official API pricing page](https://developers.openai.com/api/docs/pricing), accessed 2026-10-28, gives standard short-context USD per million input / cached input / output: Luna $0.10 / $0.01 / $0.50; Terra $1 / $0.05 / $5; Sol $2 / $0.10 / $10; Astra $10 / $1 / $50. Price = `((input - cached) × input_rate + cached × cached_rate + output × output_rate) / 1,000,000`. The standard tier is a comparison assumption; the actual tier remains unchanged. Per-request context length, cache eligibility and writes, other tiers, regional uplift, tools, retries, hardware and human time can change costs. No cross-model cache transfer is assumed. All-cache-miss totals below are a separate sensitivity; they do not establish long-context or fast-tier prices. ## Conditional API break-even sensitivity

Keep A's expert review gates and imagine C's additional Luna and Terra activity, but allow experts to receive narrower source-supported packets and avoid genuinely duplicated context. The extra Luna plus Terra cost is $0.19355 for pump and $0.29650 for foundation. To break even, **Sol and Astra together would have to save at least that amount compared with A**; this is a sensitivity, not evidence such savings exist. At standard short-context rates and assuming only uncached input is removed, the pump amount equals 96.775k Sol input tokens or 19.355k Astra input tokens; the foundation amount equals 148.25k Sol input or 29.65k Astra input tokens. Alternatively, assuming only output is removed, the equivalent is 19.355k Sol or 3.871k Astra output tokens for pump, and 29.65k Sol or 5.93k Astra output tokens for foundation. Combinations can also meet the threshold. Cached input is cheaper and would require a larger reduction. These are illustrative arithmetic equivalents, not proposed mandatory cuts; they include the risk that some values approach a baseline's whole expert budget. The strategy fails if direct source reading, sufficient reasoning, architecture or Astra checkpoints need those tokens. C itself budgets more expert usage, so its actual forecast does not realize these hypothetical savings.

A smaller **conditional success** illustrates the screening mechanism without assuming break-even: start with A's expert budgets and C's Luna and Terra budgets. If screened packets replace 20k uncached Sol input tokens and 2k Sol output tokens of duplicated lookup/rework, plus 1k Astra output tokens of repeated reasoning, the modeled expert saving is $0.1100. Pump's total becomes $2.19725, still $0.08355 above A. Conversely, if missing packet context requires Sol to reconstruct 10k uncached input tokens and Astra to produce 1k additional output tokens, expert cost rises $0.0700 and the total becomes $2.37725, $0.26355 above A. These variants use the same expert gates and differ from C's conservative expert counts; neither savings nor reconstruction is observed. ## Tradeoffs and weekly allowance

More scouting can expose omitted evidence or avoid expensive rework, but screening can also add overhead without reducing expert work. In the C forecasts Luna and Terra rise while Sol and Astra remain at least as large as A; modeled API cost rises by $0.43355 for pump and $0.7865 for foundation. This is a failure-to-save case, not a prediction that the extra work adds no value. Relevant missing evidence, missed contradictions, quality of accepted findings, repair frequency and elapsed time need actual matched observations. Early Sol architecture and timely Astra measurement/trust-boundary review are required even if that raises usage. If a screened packet loses decisive context, the expert must inspect the source and the work can cost more still.

The user-provided unitless weekly-usage planning index is Terra = 1, Sol approximately 10, Astra approximately 20, and Luna = 0.1. It is not verified or calibrated to actual comparable workloads or weekly allowance use, and is not API dollars, paid-credit prices, percentages, or token multipliers. Neither the above costs nor token totals can calculate weekly pressure.

The following workload-normalization algebra is the original historical unknown-λ sensitivity analysis; its scenario equations and conclusions are preserved. It assumes one comparable workload unit per model in A and, in an alternative, Luna 2.5, Terra 1.5, Sol 0.8 and Astra 0.8. Let Luna's unknown cost per normalized unit be λ ≥ 0 and assume those units really are comparable. A then costs `31 + λ` and the alternative `25.5 + 2.5λ`; pressure falls only if λ < 11/3, because reducing Sol and Astra by 0.2 units each avoids 6 index units while extra Terra costs 0.5. Neither those avoided units nor λ were measured in that original analysis. The current user-set planning choice is λ = 0.1; it is not a measured or calibrated factor. If, conditionally, that choice is applied to the same hypothetical equations, A costs `31.1` and the alternative `25.75` index units, so the alternative is lower under those assumptions. The alternative still cannot reach half the baseline for any nonnegative λ: `25.5 + 2.5λ` is always greater than `(31 + λ)/2`. Luna reaches half of the alternative only if λ ≥ 10.2, which in this example is incompatible with reducing total pressure. In general, achieving half requires `H_current + L_current × λ ≤ (H_baseline + L_baseline × λ)/2`, where H is all non-Luna normalized cost; this requires enough actual strong-model work avoided as well as a sufficiently low Luna factor. A target share is not a reason to add work.

A real assessment would define and pre-register matched acceptance, cases and baseline, record attributed per-model usage and actual cache/tier/request lengths without double-counting cumulative samples, track source-supported findings and contradictory or missed evidence, preserve original failures and compare total review/repair work and elapsed time. Weekly allowance needs isolated or otherwise attributable observations and calibration; the present exercise supplies neither. The forecast assumes a Terra-high coordinator and preserves the existing Luna-high, Sol-ultra and Astra-medium pins, authorization boundaries, and actual service tier; it does not assert the primary model was changed.
