# Result

The importer kept up in this short, controlled benchmark, but whether it can sustain 1,000 records/s on production storage remains unverified. The final run measured 0.002622 s per 1,000 incoming records, leaving 0.997378 s (99.74% of each second) of average processing margin; its 30 measured batch times ranged from 0.002547 to 0.002933 s. An earlier run measured 0.003298 s per 1,000, with 0.996702 s margin. These figures are estimates, not guaranteed capacity or tail latency.

`bench.py` now exercises the normal `import_lines` path including JSON parsing, validation, SQLite inserts and a commit per 1,000 records. It uses 2 warmup and 30 timed batches of unique, short, valid records, checks acceptance and storage counts, and creates the database on the current directory's filesystem. Input generation is outside the timer. README documents assumptions and limitations.

Commands run from this directory:

- `python3 -m unittest && python3 bench.py`: 2 tests passed; final benchmark results above.
- `python3 bench.py && df -T . && python3 --version`: earlier benchmark results above; `df` reported `/tmp` as `tmpfs`; Python 3.13.5.

The tmpfs result does not measure durable physical disk I/O. The short test also does not include network/arrival handling, larger records, database growth over a long run, or contention. To establish sustained production capacity, run the benchmark and a longer representative feed on the actual destination filesystem and workload; no such environment was provided.
