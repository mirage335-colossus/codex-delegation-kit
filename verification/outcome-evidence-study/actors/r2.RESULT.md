# Result

Implemented a batch continuous receiver that searches unknown arrival time and integer frequency offsets from -8 to +8 Hz using only sample rate, symbol length, message length and the samples. The actual bit count and symbol duration are assumed known; waveform generation and reusable references are prepared before timed processing. The tests and benchmark read the current `cases.json` on each run. The aligned discriminator is still checked, but only asserted to recover at zero offset because it cannot correct frequency offset. Documentation describes the method, commands and limits.

Commands and results (this container, Linux, Python 3.13.5, 12 CPUs visible):

- `python3 -m unittest -v` — all 5 tests passed, covering every current case and a mismatched-input check.
- `python3 benchmark.py --seconds 0.5` — repeated full serial acquisition and decision, after a warm-up, for at least 0.5 s of processing per case:
  - local: bits 101101/101101, start 32/32, offset 0/0 Hz; 0.008292 processing s/input s, 99.2% real-time margin, 120.6 input s/wall s; 2.55 MiB traced peak and 1367 MiB available physical pages.
  - offset: bits 010110/010110, start 41/41, offset 6/6 Hz; 0.008972 processing s/input s, 99.1% margin, 111.5 input s/wall s; 2.55 MiB traced peak and 1397 MiB available physical pages.
  - weak: bits 110010/110010, start 29/25, offset -5/-5 Hz; 0.009355 processing s/input s, 99.1% margin, 106.9 input s/wall s; 2.53 MiB traced peak and 1392 MiB available physical pages. The bits succeeded even though timing was four samples late.

Input duration includes leading and trailing samples. The traced peak includes the prepared input and reference plan plus processing allocations, and the rough available/peak ratios were 537x, 548x and 550x respectively. These are snapshots rather than safe worker counts: interpreter baseline, native memory, other workloads, changing available memory and other limits are excluded. The benchmark did not detect a finite cgroup-v2 memory cap at its inspected root. The CPU ceiling is serial throughput only, not measured multi-core scaling. The batch receiver waits for the whole message, assumes a bounded offset grid and known symbol and message lengths, and does not detect signal presence. These three deterministic noise realizations do not establish broader recovery probability or hardware capacity; longer and wider trials and parallel scaling remain separate work if those claims are needed.
