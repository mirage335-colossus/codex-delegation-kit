Extended `bench.py` to time the normal JSON parse, validation, SQLite insert and per-1,000-record commit path. It warms up five batches, measures 300 batches of unique small valid records in a temporary file-backed database, verifies all rows and reports mean, p95, maximum, throughput and the one-second real-time margin. Input construction and database setup are excluded.

Commands and results (from this directory):
- `python3 -m unittest -v`: 2 tests passed, including after the final benchmark code edit.
- `python3 bench.py` (four runs): mean 3.285, 3.134, 2.980 and 4.196 ms per 1,000 records; respective margins 996.715, 996.866, 997.020 and 995.804 ms. The last run measured 238,315 records/s, p95 6.068 ms and max 7.575 ms.
- `python3 -c 'import platform,sys,tempfile; print("Python:", sys.version.split()[0]); print("OS:", platform.platform()); print("Temporary directory:", tempfile.gettempdir())'`: Python 3.13.5; Linux; `/tmp`.
- `df -T /tmp`: tmpfs.

The measured workload suggests this computer can keep up with 1,000 records/s with substantial margin. The measured 300,000 records represent 300 seconds of incoming traffic, processed back-to-back in about one second, not a 300-second soak test. Storage is memory-backed, and generation, network delivery, other system work, larger or invalid records, a larger existing database, different batch sizes and persistent-disk latency are not represented. Production confidence requires a longer test with representative input and actual storage. README.md documents the basis and limitations.
