# C6 architecture review

1. **The sealed status can outlive an unresolved training model.** If the retained erasure bound is unsupported, the wrapper marks fit unresolved, then still forecasts with allow_approximation=True, checks only guarded intervals, and writes top-level status='prediction_sealed'. A consumer could read that status as an admissible phase refresh even though the erasure branch is unresolved. **Predicted observation:** with an unsupported erasure bound, output can still be prediction-sealed if the approximate forecast stays within budget. **Cheapest check:** exercise/inspect that branch and confirm the produced status plus downstream acceptance semantics. **Action:** distinguish sealed-for-review from accepted/usable, or block acceptance when unresolved. **Preserve:** sealing the prediction for audit while retaining the unresolved reason.

2. **Fixture matching does not visibly bind the local CPU evidence to the measured fixture.** The prepared bytes and validity mask are matched to remote and old_trace; local CPU evidence supplies the erasure sample and updated model, but the wrapper shows no corresponding local input-hash assertion. If local evidence was produced from a different fixture, the refreshed timing and retained bound may be combined across inputs. **Predicted observation:** mismatched local fixture provenance can pass these displayed hash assertions. **Cheapest check:** inspect local evidence for fixture hashes and compare them to data_sha/mask_sha; if absent, verify the local calibration’s fixture identity through an explicit stable key. **Action:** enforce that binding or mark the local evidence as not fixture-comparable. **Preserve:** exact hash checks against remote and prior holdout.

3. **The output is written before the fresh holdout, so lifecycle status must be explicitly provisional.** The packet says this wrapper ends at prediction sealing and contains no execution outcome, while its schema/status already says prediction_sealed. If the fresh receiver holdout is a later stage, the artifact itself needs a clear pending-holdout state so interruption cannot leave a seemingly complete refresh. **Predicted observation:** a valid output file can exist with no fresh-holdout result. **Cheapest check:** confirm the writer/consumer contract treats this schema as pending and cannot promote it without the later holdout. **Action:** encode holdout-pending separately from holdout-accepted and bind the later result to the sealed prediction hash. **Preserve:** the pre-holdout prediction hash and one-shot holdout design.
