# C6 general review

The wrapper has useful identity controls before spending the fit: it asserts the prior CPU trace matches its input, binds the prepared data and validity hashes to both GPU and prior holdout, and matches public geometry and acquisition coordinates. That makes this a plausible narrowly scoped measurement setup. The packet is pre-execution, so it establishes no runtime outcome or actual fit reliability.

1. **Unresolved erasure bound does not block the sealed prediction.** If `fit` lacks an interval or its upper bound fails the retained erasure ratio, `supported` is false and the code marks `fit` unresolved, but it still forecasts, checks budgets, and seals a prediction. Predicted observation: `retained_erasure_bound_rechecked: false` alongside a non-missing prediction (possibly within holdout budgets). Cheapest check: inspect this boolean and `training_observations.model_status` in the sealed object. Action: treat that state as unresolved and do not spend the fresh holdout to validate it; require the erasure bound to be supported before proceeding. Preserve the old erasure evidence and thresholds.

2. **Matching setup identity does not establish matched measured work.** The wrapper checks geometry and acquisition coordinates, but the supplied validator distinguishes exact physical/public work from bounded diagnostic drift. Predicted observation: the fit may show a different adaptive work regime, endpoint/projection, or work counts despite matching setup assertions. Cheapest check: run the applicable `_check_fine(..., nominal=False)` comparison on the resulting CPU observation and matched GPU observation; inspect `exact_work` and driver ratios. Action: keep the refresh only if physical/regime checks pass and diagnostic drift remains within the existing limits. Preserve per-phase mixed-time evidence rather than replacing unrelated measurements.

3. **Fit-time operating-condition change can make the prediction unrepresentative.** Conditions are captured before fitting and again before the external holdout, but no gate is shown for a material change. Predicted observation: frequency, temperature, or another operating field differs across those snapshots and could move CPU timing. Cheapest check: compare the two recorded condition objects before accepting the prediction. Action: if materially changed, mark the fit non-comparable and defer the holdout pending a controlled measurement. Preserve the before/after snapshots and the single-holdout limit; do not repeat until pass.
