# C3 general review

1. **Parity status can be vacuously accepted if the case set is empty.** At `triad_gpu_workload.py:274–276`, `all(...)` is true when `report['cases']` is empty; with positive CUDA allocation, the report becomes `short_fine_work_parity_observed` without comparing any records. The excerpts do not establish whether an empty case list is possible, so this is a conditional gap, not a confirmed defect. Cheapest check: feed the acceptance path an empty `cases` list with positive `cuda_peak_allocated_bytes`; require `unresolved` (or a distinct no-cases status). Also assert at least one case and one parity stratum before accepting parity.

2. **The success status establishes parity, not a usable timing comparison.** `compare_work` at lines 162–169 checks work and score equality only; the status condition at lines 274–276 checks parity and nonzero allocation, with no shown validation of timing samples, synchronization, or finite/positive durations. The status name is appropriately scoped to “parity observed,” so this is not evidence of an implementation defect. But if callers interpret it as acceptance of a throughput estimate, a passing result could mask absent or invalid timing data. Cheapest check: make timing samples absent or non-finite while parity passes and inspect the report/consumer; keep parity status separate from any timing-acceptance status, and validate paired synchronized samples before reporting an estimate.

3. **Paired records are assumed to be positionally comparable.** `compare_work` uses `zip(cpu, cuda)` and checks each pair, but the excerpt shows no record identity/order check. If either sampler reorders rows while retaining the same work and close scores, the equality result could compare unlike observations and report false parity. The shared coordinates and prepared input in `_case_probe` reduce this risk, but do not prove record ordering. Cheapest check: verify a stable case/coordinate identity for each paired record (or deliberately permute one device's records and confirm the comparison rejects it); add identity pairing only if records can be reordered.

**Preserve:** Keep work equality and score closeness as separate booleans, and require both via `all(check.values())`. That makes the reported parity conjunctive and keeps score tolerance independent of timing.
