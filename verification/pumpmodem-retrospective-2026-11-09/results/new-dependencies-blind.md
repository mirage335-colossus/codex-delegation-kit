## Call chain and synchronization

`tools/triad_gpu_workload.py:339–367` creates a `CompleteBitReceiver` for each device; the receiver constructed at `:343–347` is the public entry point. In `triad_receiver.py`, `FineSession.__init__` creates one basis provider/cache and wires that same provider into nominal and adaptive lanes (`:205–209, 230–255`). It reuses the shared executor for basis generation and hypothesis work. `FineSession.push/finish` forward to the `PracticalTrackingReceiver` (`:273–309`). `CompleteBitReceiver` also uses that executor for independent coarse partitions (`:637–698`); those are joined before candidate selection/refinement (`:689–755`).

`PracticalTrackingReceiver.push` visits nominal then adaptive sequentially (`triad_tracking_receiver.py:720–735`). They are separate likelihoods with a fixed half/half mixture, so their mathematical outputs are independent; their sequential order is an implementation choice. However, they share the provider/cache, and naive outer-pool lane tasks that themselves submit inner tasks to the same bounded pool can deadlock or starve. They also each own mutable timing/channel state, so a lane cannot have overlapping pushes.

Within each lane, `_score_segment` predicts timing at the segment boundary, fixes the current timing-state bank, computes block emissions, then calls `_observe_segment` (`triad_tracking_receiver.py:206–265, 551–567`). `_observe_segment` updates global timing weights/pruning and selects channel posteriors for the next segment. This makes the **segment barrier real**: later segment candidate identity/state/weights depend on completed current-segment emissions and pruning. The lane also cannot advance block `b+1` for a state/model before that runtime finishes block `b`, because `IncrementalGaussianReceiver._score_block` updates mutable Gaussian filter state (`triad_incremental_receiver.py:286–382`). Thus a **per-block join is currently required** before that filter's next block. Timing is not updated or pruned per block, only per segment.

## Boundaries worth comparing

1. **Current: per-block task batch.** `_score_block` builds jobs across coherence models and optional candidate shards, submits them, and joins all futures before recording block progress (`triad_incremental_receiver.py:352–382`). CPU sets `hypothesis_shards=1` (`triad_receiver.py:250–255`), so with four default coherences it exposes only four model jobs for up to 12 workers. GPU requests roughly `ceil(workers/coherences)` shards/model, up to 12 jobs. Existing CPU FP64 basis projection is also independently split/joined per block at `:257–284`. This likely leaves CPU workers idle.
2. **Preferred investigation: widen the *block* batch across candidate × model states, retaining the block boundary.** One batched state-update/kernel invocation can expose all candidate/model work (e.g., 64 candidates × 4 models = 256 independent updates), while the next block waits for all states. On CUDA this is the most natural larger batch and avoids changing timing/pruning semantics. This may require reorganizing per-runtime jobs; raising `hypothesis_shards` alone may not suffice. Preserve candidate order, coherence mixture, FP64 evidence accumulation, and output tensors/state. Keep one executor and do not wrap current `submit` paths in an outer pool.
3. **Do not batch across segments or whole lanes as an initial change.** Segment emissions feed global `SparseTimingForward.observe`, posterior selection, pruning without renormalization, and subsequent basis state count; removing this boundary changes required adaptive output/state. Concurrent nominal/adaptive is a later alternative only if it uses non-nested scheduling and safely serializes or partitions shared cache/source ownership; no source evidence establishes the cache as safe for concurrent mutation.

The strict quiet-sample statistic is accumulated from complete projected likelihood blocks in `IncrementalGaussianReceiver._score_block` (`:303–315`), and `finish` only reports complete after the declared endpoint (`:474–490`). Keep each public block/calendar and lane coverage unchanged.
