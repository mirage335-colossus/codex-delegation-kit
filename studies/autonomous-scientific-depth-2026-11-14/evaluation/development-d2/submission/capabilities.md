# Available assistance and external access

This is the fixed opportunity for the whole task, shared by the owner and every
helper. It is available capacity, not a target or minimum: 2,000 web request
items, 100 public browser content actions and 80 other supported public read-only
acquisition calls. The original elapsed deadline remains unchanged. Up to 12
task participants may be active simultaneously, including the owner; at most 32
helper assignments may be started. A continuation of an existing assignment uses
the same scope, authority, evidence and limits. A replacement or distinct new
scope counts as a new assignment. The coordinator queues requests if slots are
unavailable and reports factual delivery status.

Use `web-recipe.md` for every web request. The shared allocation ID is `case`.
Each search/open/click/find/screenshot item consumes one operation, including
items batched in a single call, errors and duplicate reservations. The wrapper
uses a lock and checks admitted limits; it is cooperative accounting, not a
security interceptor. It does not observe unwrapped calls or certify source
understanding. Record unwrapped activity or logging failures immediately.

Public browser and other acquisition calls are separately reserved before use:
send `/root` a request ID, surface, exact URL or tool/action, requested number of
content actions/calls, and recipient. After admission, use only the reserved
scope and return actual actions, raw results or artifact pointers and failures.
The coordinator counts the reserved amount conservatively if execution status
is unknown. Browser initialization documentation and required completion-control
calls are recorded separately from content actions. Request continuations within
the remaining fixed allowance when needed. Do not silently move requests to an
unmetered surface. A depleted allowance cannot be evaded through another surface.

Native web and public browser tools may be used where available. Follow their
tool documentation; use primary sources for technical claims and retain access
limits. A source fetch failure may justify an authorized public alternative.
Browser access may be available only in the main chat. You may request exact
URLs and actions there, with raw results returned to you. Some PDF views may be
blank and some direct binary opens may be blocked; neither proves source
verification. A web screenshot request can return a plain error string without
image data. Inspect the actual returned content. If a response contains supported
ImageContent blocks, the documented `functions.image` helper can display them;
printing serialized image data alone is not visual inspection.
Service safety/permission restrictions remain binding and do not authorize
another route, agent or model for the restricted operation. There is no new
network-capable controller backend or implied shell-network permission.

Every helper receives this same authority and pooled opportunity, the common
guidance, its role instructions and your exact scoped assignment. It reads only
the common project, own-task authorized evidence and its assigned paths. Request
additional help using exact role and prompt text through `/root`; the coordinator
does not change the scientific agenda. State which existing participant should
receive the result. The owner controls internal allocations, reserve and use.
