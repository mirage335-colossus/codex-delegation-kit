# Prospective scientific profile implementation

This study-only extension is preparation infrastructure. It is not a selected
candidate, a frozen real episode, launch approval, or a successful scientific
result. The ordinary smoke path keeps its V5 default, read-only native sandbox,
twenty-minute allocation and existing two-child request. The scientific path
requires an explicit profile JSON and never falls back to that source snapshot.

An operator must first select and independently freeze the candidate. The
profile JSON has exactly these fields (placeholders below are not a runnable
episode specification):

```json
{
  "schema": 1,
  "name": "scientific-v1",
  "candidate_label": "EXPLICIT_REVIEWED_CANDIDATE",
  "snapshot": "/ABSOLUTE/FROZEN/SNAPSHOT",
  "source_manifest_sha256": "EXACT_MANIFEST_HASH",
  "project_manifest": "/ABSOLUTE/EXPORTED/PROJECT_IDENTITY.json",
  "project_manifest_sha256": "EXACT_IDENTITY_HASH",
  "task_sha256": "620bebf24a81d2acf112c70b4c4709fe830b511e470df30ec7fd8acef3457e1a",
  "relay_services": {"public": false, "dependencies": false}
}
```

Set a service true only when the authorized operator can maintain it for the
episode. The optional preparation argument is `--profile PATH`; a simultaneous
`--snapshot` is rejected. No selected candidate or actual full scientific packet
is produced by this implementation assignment. The existing setup/preflight
operations remain separately gated by review and fresh platform approval.

Admission checks the exact 368-file, 5,805,584-byte exported project and its
canonical AGENTS.md, not an arbitrary larger fixture. It preserves the ordinary
task byte for byte and generates a separate neutral environment input. The full
candidate checkout and role pins are checked through its manifest; source role
generation calls `install.blocks`, never installation. Only whitelisted ordinary
project identity fields reach actors. Prepared file inventories and hashes,
driver/helper identity, executables, host config/gateway and frozen manifests
are rechecked at launch. Authentication is metadata-only, never read or hashed.

Scientific admission also rejects pre-existing `.git`, `.agents`, `.codex` and
`.aws` paths, including empty directories, and requires directories to be exactly
the parents of the 368 source files. After copying, a dedicated fixture helper
creates those four empty real directories only in the private exported fixture,
using non-idempotent creation and restoring the copied root's original mode.
These native protection mountpoints have a separate frozen `fixture_layout`
declaration in the prepared record; they do not change the source-file identity.
Preparation and preflight require the fixed declaration, empty non-symlink
targets and exactly the 18 source-parent directories plus those four targets.
Missing, duplicate or additional declarations, changed properties and unexpected
directories are rejected without repair. Generic relay staging and default
smoke preparation do not create these mountpoints. Older prepared operations
retain their stale driver/helper hashes and must not be migrated in place.

The profile carries one eight-hour author allocation from dispatch, a separate
45-second setup allowance and the existing 30-second cleanup allowance. It asks
for at most eleven children, preserving a stricter host allocation. Assignment
receipts count new child/scope combinations and replacements against thirty-two;
native observed child identities are only a lower bound. They do not prove
unobserved scope assignments or closed-thread capacity. The first root terminal
is retained as an independently bounded, redacted snapshot before event storage;
an event cap or later child-read failure cannot replace its identity/status.
The snapshot ceiling is 64 KiB; larger sanitized terminals retain identity,
status, byte count and hash, with an explicit omission. Every terminal result
and closure copy uses the same collector redaction. First terminal observation
immediately writes a durable close intent, then serializes the closed state with
the service. Optional final metadata reads, including a read already in flight,
receive at most two seconds instead of the remaining author allocation. Cleanup
and administrative interruption share the existing thirty-second allowance.
Collector failures and incomplete dispatch acknowledgment remain distinct from
the retained terminal. The collector never resubmits the task or asks the
primary to repair its science.

The workspace-write config uses locally verified 0.163.0 schema fields for work
and scratch, network false, and both ambient temporary-root exclusions. Returned
root configuration, local roots, instructions and ephemeral metadata are checked
before dispatch. `runtimeWorkspaceRoots` is not a read-only-root list. The native
compatibility sandbox projection is checked without claiming it proves enforcement:
the outer read-only project/global mounts independently deny project writes.
An actual synthetic bubblewrap check exercises work/scratch writes and denied
project/global/inbox/allocation writes. Native workspace-write enforcement still
requires the approved prospective runtime observation; no model was launched here.

The shared author meter reuses research_meter.py unchanged. Actors reserve
canonical root-service public requests in work/outbox. The operator performs
`claim` with a reference to an actual scope/permission review, executes the exact
request through its supported tools once, then `publish` with the claimed hash,
raw response/error file, actual operation and invocation counts and optional ordinary dependency
file. Neither helper executes network calls. Claim receipts retain exact outbox
bytes from one bounded descriptor snapshot; parsing, validation and hashing use
those same bytes. Response/dependency ceilings, byte counts, copies and hashes
likewise use one checked snapshot. Responses bind their request and raw artifact
hashes. Publish does not
rewrite a request, select excerpts, or add interpretation. Browser initialization
and control use the separate `browser_control` category. A count exceeding its
reservation remains a violation in the receipt. Interrupted/ambiguous execution
is not replayed automatically. Public controls and unknown batched units require
explicit operator review; the generic tool-name envelope alone is not permission.

Admission, claims, publication and closure use the same lock inode in the
read-only inbox. Lock acquisition is bounded to two seconds. A durable close
intent blocks admissions even while a prior publisher holds the lock. Responses
stage privately; after all staging writes, publication rechecks both the author
deadline and close markers at its commit boundary. A transaction already past
that final check is ordered before closure. Late/in-flight results retain their
exact raw snapshot and actual costs under operator-only control storage, with
`published_to_author=false` and `late_private_audit` disposition. They do not
enter the author inbox/dependency tree or finish a locked author-meter receipt.
These later administrative audit records are separate from locked science and
may postdate the collector's final resource summary. Duplicate claims/results
remain unreplayed, including incomplete or late dispositions.

For a capability request, the service publishes support/scientific_access.md
verbatim. For a dependency request, it verifies ordinary scope and the frozen
source revision and publishes the exact requested bytes in a separate read-only
directory. Both public and dependency services can be frozen unavailable. No
scientific selection, source lead, unsolicited next step, scheduler or additional
model owner is introduced. Native web is configured live but its input mapping
is unverified: actors must use the canonical mailbox, and observed native web
items cause a recorded unmetered-use hold. Output action schemas are not input
schemas or reservation evidence.

Stream/event/relay ceilings are finite; events stream to disk, stderr retains a
bounded tail, and storage admission reserves room for the declared collector
ceilings. After observed owned-process cleanup, author files are incrementally
hashed and made locally read-only within a bounded lock pass. This is not a
security boundary against the host file owner. Pending receipts and unavailable
history remain incomplete evidence; late operator audit cannot repair author
omissions. Cleanup uncertainty, service-closure failure or lock failure prevents an accepted
scientific run result. There is no author-disk, process-memory or token enforcement.

Before any eventual launch: retain the accepted collector smoke review; select
and freeze the candidate and ordinary packet; obtain independent patch review;
review the exact service and write surfaces; obtain fresh platform approval.
This infrastructure does not choose V7, change the scientific bar or supply a
scientific conclusion. The unchanged 89-row/48-depth evaluation remains outside
actor inputs and uses a separate post-lock evaluator allocation.
