## Frozen design before participant work

Independent authors prepare native C++ miniature applications. Three development
cases and six separate final families cover bulk visual/simulation/audio work,
sensitive state and exact counters, repeated computations/algorithm choice,
automatic capacity/precision overrides, and hardware capability reporting. Task
prompts describe product outcomes; most do not request a precision change.
Discoverable source, requirements and ordinary public checks replace supplied
route rankings. No fake format-dependent speed factors or sorted benchmark tables.

Each case must pass fixture preflight before dispatch: executable starter,
demonstrated product failure, passing witness, and a relevant bad implementation
rejected for the intended reason. Every private gate must derive from public
product requirements. Hidden inputs and reference answers are allowed; hidden
product requirements are not. Alternative correct implementations must be accepted.
Witnesses, private tests and other answers are outside the participant read scope.
Instructions and disjoint paths do not establish OS isolation.

Quality, complete required work, exact state, supported overrides and capability
reporting are binding. Demonstrate useful implementation with actual executed
outputs and memory/capacity or robust end-to-end timing. Type spelling, claimed
allocated bytes, a worker's report, or a faster isolated multiply alone cannot
establish improvement. Resource checks must inspect actual allocations or otherwise
cross-check self-reported metadata. Timing qualification is serialized after builds,
uses stable flags/input, and retains variance and measurement conditions. Do not
force-enable instructions absent from the real processor. Deny-only feature masks
test dispatch separately from physical hardware coverage.

## Participant and prompt delivery

Use fresh no-history Luna-high workers, the normal installed role, the source
compact reminder verbatim once, and explicit standing role authorization. The
installed role currently lacks that reminder. This exercises manual delivery of
source guidance, not global deployment. Surrounding role and app instructions are
common and may influence results; no clean prompt-only causal control is claimed.
Keep the main model, pins, service tier and runtime inventory unchanged.

Give each worker a private copy, owned core source and optional scratch/checks,
ordinary supported commands, a common bounded allowance, and a concise evidence
report request. No user/coordinator corrective messages during a scored run.
Compiler errors and public tests are normal environmental feedback; autonomous
repairs count separately from initially clean execution. Coordinator repairs never
count as participant success. Unnecessary requests for tuning or clarification are
failures. Actual ambiguity or broken setup is a fixture failure, retained separately.

## Iteration and completion

Development results may drive general prompt revisions. Retain every original
patch, failure, interruption, public check and protected-file audit. Refreeze a
revised prompt before further runs. Do not fix individual task code for a worker.

After development stabilizes, freeze the candidate and run two fresh workers on
each of six untouched task families. Each final run must satisfy every applicable
product gate with an executed useful patch, truthful evidence and no corrective
user/coordinator input. Aggregate scores must not hide a failed requirement.
If a final case informs a prompt or fixture change, retire it from untouched
evaluation, preserve its outcome, and prepare genuinely new final cases for the
changed coverage. Repeating a known case is regression evidence, not a new holdout.

The target endpoint is a complete final matrix across the tested envelope,
including both low-precision opportunities and justified wider/exact exceptions.
Report model/run/fixture limitations and all waves. Missing cost or effective
runtime telemetry remains missing. This study grants no cloud spending, global
installation, pumpModem edits, commit or publication permission.
