Amendment frozen after the sixteen original owners requested no helpers and all
passed functional acceptance. Two original routine-control arms failed protected
file ownership. Neither instruction version showed an advantage; the original
default-adoption criterion remains unmet and cannot be rescued by this extension.

with the existing CPU Python environment. The projection opportunity is known
from the historical retrospective: this is exploratory replay, not held-out
validation or an uninfluenced natural-task sample.

Four fresh Luna-high owners receive the unchanged baseline/candidate instruction
texts crossed with solo/fixed-parallel-support. Supported owners receive two
independent read-only helpers, concurrently dispatched, answering exactly:

1. Which computations are unnecessary for the supplied workload, and what existing
   mechanism could replace them?
2. Which projection and caller invariants constrain an alternative, and what small
   executable comparison could reject it?

Helper availability is assigned by the protocol, not triggered by the owner.
This measures supplied support, not autonomous activation or a comparison of
parallel versus sequential scheduling. Support adds work as well as concurrency;
no effect can be attributed solely to scheduling. All roles use only their
participant-safe source, task and environment. No facilitator supplies algorithm
hints or private oracle content. Helpers preserve the frozen source and use owned
scratch; owners edit only their private implementation. Tests/contracts stay
protected.

Owner inspection gets four shell invocations; subsequent implementation and
validation get ten, preserving fourteen total. Each helper gets four. Commands
finish within sixty seconds; owner stages have five-minute wall allowances,
helpers four minutes. Record overruns and all original failures. Helpers start
alongside initial owner inspection. Return their reports verbatim only after the
owner's initial findings are sealed. If reports are pending, the owner may use
four of its remaining invocations on independent work, reserving six for later
integration. Solo owners get the same remaining allowance without helper input.
Use a seeded frozen dispatch order. Record actual overlap and delivery delays.

Before dispatch freeze participant-visible manifests, hidden evaluators and a
passing witness. Acceptance compares with the original implementation for real,
complex, batched, strided, singleton, multibin and valid-row inputs, observes full
FFT calls independently on the specified workload, and exercises an existing
incremental receiver check through the real projection boundary. Baseline must
fail the requested work-elimination condition; the witness must pass every check.
This establishes a bounded computation reduction, not whole-receiver throughput.

Grade artifacts and unchanged tests independently, inspect evidence of helper
contribution before the owner independently found it, and retain every outcome.
There is no intervention-reference phase or further case expansion in this
extension. After it, report useful supplied support or no demonstrated benefit.
General recovery wording remains experimental; autonomous user-like intervention
has not been demonstrated by a forced-support experiment.
