# Autonomous recovery exercise protocol

Frozen before participant dispatch on 2026-11-09. The user asks for parallel AI
development work that makes useful course corrections without waiting for user
intervention. These are executable, synthetic development exercises, not a new
pumpModem performance campaign or proof of general model reliability.

## Comparison

Four cases: wrong/partial execution path, repeated symptom repairs, mistaken
constraint/decomposition, and a productive routine-fix control. Fixture builders
must demonstrate a failing baseline and a passing witness before freezing. Their
oracle, witness and intervention text are excluded from participant copies.

Each case has four fresh Luna-high owners: baseline instructions with sequential
helper scheduling, baseline with parallel scheduling, candidate with sequential
scheduling, and candidate with parallel scheduling. The baseline is the exact
`COMMON_INSTRUCTIONS` of the uninstalled five-file performance proposal. The
candidate replaces its performance-specific cue with the frozen general recovery
cue. All other wrapper text, source, acceptance contract, model/effort, helper
availability and work allowances match. This tests prompt content delivered in
native exercise packets, not installation, provider isolation or all kit rules.

The owner can request zero, one or two helpers. The coordinator relays its exact
questions; it does not invent a better question or supply a case-specific hint.
Helpers use a fixed neutral instruction and the frozen baseline fixture, not
another participant's patch. Sequential scheduling completes the first requested
helper before dispatching the second; parallel scheduling dispatches both before
waiting. With fewer than two requests there is no realized scheduling contrast.
The scheduling label is concealed from owners; their request opportunity matches.

## Stages and common allowance

1. Owner inspection: at most four shell invocations, read-only source and bounded
   diagnostics. Return a JSON request with up to two independent helper questions,
   and an independent next action. No patch yet. The task does not label its trap.
2. The coordinator starts eligible helpers and resumes the owner for up to four
   shell invocations on its independent action. Each helper gets at most four
   shell invocations and returns evidence, an executed discriminator where useful,
   and limits. Helpers have read-only source and private scratch, no production
   patch. Owner work and helper work may overlap, but no owner receives unreturned
   findings. The coordinator preserves actual dispatch/return timestamps.
3. After helper results, the owner gets up to six more shell invocations to
   integrate evidence, finish the patch and run acceptance. An owner requesting no
   helpers gets the same remaining allowance, without fabricated helper work.

The maximum is fourteen owner and eight helper shell invocations per arm. Each
invocation has a 60-second execution limit; each owner stage has a five-minute
wall allowance and each helper a four-minute allowance. These include model/tool
time after dispatch, excluding coordinator delay before dispatch or resumption.
The coordinator records overruns as protocol deviations and stops only owned
work. No check may leave background descendants. A shell
invocation can contain related operations, so also retain actual commands and
usage; invocation counts do not establish equal computational work. Owners and
helpers have finite task scope, local standard-library execution and no network,
installation, global configuration, commits or publication. Do not spawn nested
agents. The coordinator supplies routing authorization and notes the initial
Astra consultation is already satisfied. No recursive completion gate applies.
Role, service or tool restrictions remain binding. Pause a setup-invalid case
instead of quietly rescuing a favored arm. Preserve failed attempts and correction
history. Extra work after the common allowance is assisted or out of protocol.

Only owners edit their private `source` copies; fixture tests/contracts are
read-only. All use Python 3, existing local shell tools and the same environment.
Instruction-based separation in a shared filesystem is not an OS sandbox.
No participant reads oracles, other runs or reports. Synthetic cases are small
enough for local checks; elapsed results are not hardware benchmarks.

Run the first two recovery cases as one batch, then the decomposition case and
routine control as a second. At most eight owner stages and sixteen helpers are
active in a batch, subject to actual remaining capacity. Freeze a seeded shuffled
arm order before dispatch and use it for ready-arm dispatch; preserve timestamps
and coordinator delay rather than attributing those delays to model reasoning.
The mandatory request checkpoint is shared orchestration scaffolding: these
trials do not measure spontaneous dispatch in an unrestricted session.

## Outcomes and intervention reference

Primary outcome: independent evaluator acceptance against the actual requested
entry point and invariants, with original tests unchanged. Secondary evidence:
whether an ineffective assumption was corrected, the inspected source or executed
check supporting that change, whether a helper contributed information used by
the owner, duplicated or irrelevant work, unsupported redesign and setup failures.
Score patches and command evidence before persuasive summaries. Preserve each
arm's misses and the routine control's unnecessary work.

An independently frozen one-sentence user-style intervention is given to every
arm that fails independent acceptance, after all autonomous results in its batch
are sealed; do not select only a promising failure. Allow four additional
shell invocations and record this as an assisted reference, not autonomous success
or an equal-budget comparison. The intervention is prewritten before outcomes and
must challenge the framing without giving the implementation answer. If no arm
fails, report a ceiling effect instead of manufacturing an intervention benefit.
This is an assisted continuation with extra budget; improvement cannot be
attributed to the hint separately from the extra opportunity to work.

Record owner/helper identities, actual requests, dispatch/completion times, patches,
commands, evaluator results and available model/usage telemetry. Compare total
work and elapsed time separately, including helper setup and owner integration.
Shared-run contention, coordinator dispatch delays, small sample size and absent
helper requests limit concurrency conclusions. Source-directed course corrections
are not measured historical hours or subscription savings.

## Decision rule

Do not adopt wording merely because it mentions parallelism or produces more
requests. For default adoption, require better independent acceptance in at least
two matched case/scheduling comparisons spanning two recovery cases, or both
scheduling comparisons of one recovery case, with source/command evidence of
useful course correction. Require no acceptance regression elsewhere and no extra
helper dispatch or speculative redesign on the routine control. Lower elapsed
time alone does not meet this rule; report workload and scheduling effects
separately. If this rule fails, retain the exercise findings and at most an
explicitly experimental optional recipe, not an efficacy-backed default.

Mixed or ceiling results warrant narrowing or rejecting the change, with no
claimed efficacy. Do not tune on these cases and call a rerun held out. If all
recovery arms pass, one harder new transfer case may probe the ceiling using the
unchanged candidate; it does not replace any original case. A bounded transfer
case may also test a meaningful first-wave difference. Freeze it before dispatch
and label this adaptive extension exploratory. Mandatory
Astra arbitration/completion reviews remain the main chat's responsibility.
