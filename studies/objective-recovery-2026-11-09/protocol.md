# Historical decision exercise — frozen before dispatch

This six-owner, two-helper Luna/high exercise follows Astra's review of the
actual pre-intervention decision. It tests recovery from a supplied checkpoint,
not ten hours of endogenous anchoring, production speedup, or deployment efficacy.
No further cases or difficulty changes will be added after observing results.

Two owners receive selected existing policy and backend instructions; two receive
the same text plus the short candidate cue; two baseline owners receive a shared
pair of fixed parallel helper reports. Each owner has twelve shell invocations
and ten minutes; every arm can request up to two bounded helpers. Each helper has
four shell invocations and three minutes. No forced request checkpoint is used.
Invocation limits count shell tool calls, not individual Python statements; a
command must finish within sixty seconds. Limits are instructions, not enforcement.

Inputs, prompts, assignment map and hashes are under `freeze`. Participants have
fresh contexts, private scratch directories and instruction-separated access in
a shared filesystem, not OS isolation. Later user steering and scout conclusions
are withheld. The experimenters know the historical failure. The candidate was
written after inspecting it; this is retrospective, not a held-out evaluation.

The baseline is an explicitly selected excerpt of existing instructions, not a
complete reproduction of the original long-running agent context or a deployed
app-server comparison. All original hard task and permission boundaries apply.

## Fixed helper assignments

1. Examine whether the proposed decision follows the original objective and
   measured tradeoffs. Verify decisive arithmetic or evidence where feasible.
2. Examine available work, dependencies and resource constraints in the frozen
   source/trace. Identify a concrete discriminator and execute a bounded check.

Neither receives a prescribed answer or later steering. Both run concurrently
with the supported owners. Reports are delivered verbatim as they become ready;
corrections remain separately visible. A shared evidence set with two recipients
is one helper discovery replication, not two. Owners retain integration judgment.

## Separate assessment dimensions

An independent reviewer receives the sealed owner outputs and packet without the
arm map or candidate cue. It must inspect actual scripts/results and classify:

1. **Objective fidelity:** does the owner preserve the user's stated value of
   practical utilization and cross-machine defaults, distinguishing the failed
   predeclared gate from sufficiency for the user's objective? Rejecting an
   unsupported production change can be correct; merely treating 15% as a user
   requirement is not. The exercise does not require declaring the gate passed.
2. **Measurement correctness:** does an executed check recompute relevant raw
   ABBA observations and correctly distinguish resident service, cold lifecycle,
   busy-core equivalents and source identities? Repeating summary fields alone
   is weaker than an independent calculation; record this distinction.
3. **Executed discriminator:** is there an actual source/trace/resource check
   bearing on ready useful work versus necessary dependencies, or a supported
   alternative? Record precise coverage. A script that only prints desired prose
   is not evidence, and hypothetical overlap is not measured CPU speedup.
4. **Supported action:** does the owner take a concrete in-scope step and identify
   the next feasible operation, including missing prerequisites, instead of only
   recommending more parallelism? Exact dirty ABBA source is unavailable; retaining
   candidate evidence and pursuing source recovery or a source-bound new test can
   be valid. Unchecked deployment is not required or authorized.

Do not collapse these into a single success count. Separately assess helper
requests, actual concurrency, delivery, new information, corrections, and owner
use. Source-bound records take precedence over model claims. Preserve all setup
failures, unsupported assertions and budget deviations. A fresh-context ceiling
is a valid outcome and does not explain why the original agent remained stuck.

## Disposition

Keep the earlier twenty-owner study unchanged apart from a relevance correction.
This exercise can support narrow observations and semantic clarification of kit
guidance. Six runs cannot establish a reliable autonomous trigger or causal
parallel speedup. Supplied support is not spontaneous activation; additional
helper effort is a confound. No global installation, receiver edit, commit or
publication is part of this exercise. Review results before deciding whether to
deliver any candidate wording beyond an experimental recipe.
